// 特性

一个页面，管住所有本地服务

SillyTavern、Ollama、各种 Agent 项目……每个都在不同目录、靠不同的 bat 拉起。工作台把它们变成一张张卡片，集中管理。

🗂

卡片式管理

项目名称、简介、路径（点击复制）、逐端口探测的运行状态、依赖项、标签、备注，一卡尽览。

📚

分组

自建分组，项目拖拽入组；分组可重命名、拖动排序、一键解散——解散后项目自动移回未分组。

▶️

启停控制

启动 / 停止 / 重启 / 一键打开浏览器；运行状态每 5 秒自动轮询刷新，端口状态逐个点亮。

🐳

三种启动器

script、docker、static 各取所需；前端按钮按启动器的能力声明自动渲染。

📋

日志查看

每个项目的启动输出就地查看：内存环形缓冲 + 落盘 data/logs/，不必翻黑窗口。

🤖

AI 同事接入

REST API + 自描述 Schema：其他 AI 建完新项目后，一个 HTTP 请求即可注册进工作台。

🔁

自举管理

工作台把自己也注册成一张卡片——「停止」优雅退出，「重启」经引导进程自动拉起新实例。

🌗

亮色 / 深色主题

顶栏一键切换，默认跟随系统偏好，手动选择会记住（本页也是如此）。

🔒

本地优先 · 轻量

默认只监听 127.0.0.1；可选 Token 鉴权。后端仅 1 个 npm 依赖，前端零依赖零构建。

// 启动器

三种启动器，覆盖三种来路

每个项目在卡片里声明类型和字段，启动器负责把它真正跑起来、探活、停干净。

🖥

script

bat / cmd / 任意命令拉起的服务

path
bat / cmd / exe 路径，或用 options.command 自定义命令
ports
状态探测 + 停止时反查进程
urls
「打开」按钮目标，可多个
专属
options.console 新控制台窗口运行（等同双击）；options.processMatch 按命令行匹配进程兜底停止；options.cwd / env / encoding 工作目录、环境变量、输出编码（如 gbk）
🐳

docker

Docker Compose 编排的服务（需 Docker Desktop）

path
compose 文件所在目录
ports
状态探测（compose ps 优先）
urls
「打开」按钮目标，可多个
专属
options.composeFile 指定 compose 文件（默认 docker-compose.yml）；更新 = pull + up -d
📄

static

纯静态页面，无需启动

path
HTML 文件或目录
ports
不适用
urls
file:/// 或 http 地址
专属
一键打开，没有启停概念

🛑 停止策略（script 型）：三层兜底，绝不误杀

很多 bat 用 start 拉起服务后自己退出，进程树断裂无法直接跟踪。工作台按顺序停止：① 本次启动跟踪的 PID → taskkill /T /F；② 对 ports 里监听中的端口反查 PID 后结束；③ options.processMatch 按命令行匹配。 三层都未命中时如实提示「进程未跟踪」，绝不误杀。

🧩 想接自己的启动方式？新增类型 = 一个文件 + 一行注册

在 server/launchers/ 下实现统一接口（start / stop / restart / getStatus + capabilities 能力声明），在 launchers/index.js 末尾 register('my-type', …) 即可——前端按钮按能力自动渲染，REST 校验自动生效，无需改前端。

// 部署

五分钟部署

环境要求：Windows 10/11 + Node.js ≥ 18（使用 Docker 启动器需要 Docker Desktop）。

01

克隆仓库

部署地址就是 GitHub 仓库，克隆到任意本地目录：

git clone https://github.com/roseion/ai-workbench.git ai-workbench
cd ai-workbench
02

安装依赖

后端仅 express 一个 npm 依赖，装完即用：

npm install
03

启动

命令行启动，或直接双击 scripts\启动工作台.bat（幂等：已在运行则只打开浏览器）。

npm start
04

打开工作台

浏览器访问 http://127.0.0.1:8787。首次启动会自动用 data/projects.example.json 作为种子数据初始化项目列表，之后随时编辑、拖拽、分组。

🏠 https://github.com/roseion/ai-workbench 前往仓库 ↗

可选环境变量

变量默认值说明
WORKBENCH_PORT8787服务端口
WORKBENCH_HOST127.0.0.1监听地址（不建议改成 0.0.0.0 对外开放）
WORKBENCH_TOKEN空设置后所有写操作需携带该 Token 鉴权

// AI 接入

让 AI 同事接入

任何能发 HTTP 请求的 AI / 脚本，都可以把新项目注册进工作台。

curl -X POST "http://127.0.0.1:8787/api/v1/projects" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "我的新 RAG 服务",
    "type": "script",
    "description": "FastAPI RAG 网关",
    "path": "D:/ai/my-rag/启动.bat",
    "ports": [8901],
    "urls": ["http://127.0.0.1:8901"],
    "tags": ["RAG"]
  }'
  • 📖字段规范由 自描述 Schema 提供：GET /api/v1/schema/project
  • ♻️支持 upsert 幂等注册：同一项目重复注册不会产生重复卡片
  • 🎛注册之后，启停 / 重启 / 打开 也全部可以通过 API 调用
  • 🔗完整接入文档（含 PowerShell / Python / Node 示例）：docs/API.md ↗

// 使用须知

边界说在前面

工作台不做黑魔法，做不到的会如实告诉你。

  • 外部手动拉起的「无端口」进程（如 GUI 程序）无法被识别状态或停止，卡片显示「未知」，可手动标记；工作台自己启动的实例不受影响。
  • bat 内 start 拉起的子服务，其输出在各自窗口 / 日志文件里（如 SillyTavern 的 startup.log）；工作台日志只捕获主脚本输出。
  • 个别含 chcp + 中文注释的 bat 与输出重定向不兼容（双击正常、经工作台报 9009）：在编辑弹窗勾选「在新控制台窗口运行」（options.console）即可等同双击，代价是不捕获其日志。
  • options.processMatch 按命令行匹配进程，关键字要足够独特，避免误杀同名进程。
